# HellStation — agent instructions

Diablo II: Lord of Destruction 1.14d, single player, running on a PlayStation 2. Built on the
Redivivus decompilation (`upstream` = jaenster/redivivus, MIT). This file is the contract. Read it
whole before touching anything; read `docs/port/PLAN.md` before planning work.

## Non-negotiables

1. **No game data, ever.** No MPQs, BIOS images, `Game.exe`, `DiabloII_macho`, `.d2s` saves,
   extracted assets or screenshots of copyrighted art in the repo, in issues or in CI logs.
   Data lives outside the tree (`$D2DATA`, default `~/d2data`). The pre-commit hook enforces it; never bypass it.
2. **Never edit generated code.** Anything whose first line is
   `// Auto-generated by ghidra-mcp - DO NOT EDIT` is off limits: all of `Source/`,
   `3rdparty/Storm/`, `3rdparty/crashy/`. An edit there compiles and then disappears at the next
   regeneration. Route around it with the forced-include prelude, the shim, link-time substitution
   or a hand-written function table. If it truly can't be routed around, it's an upstream report
   (see *Upstream*), not a patch.
3. **Commits are the owner's.** Author and committer are the repo's configured git identity, and
   nothing else. No `Co-Authored-By`, no "generated with", no tool or model names in commit
   messages, PR bodies, comments, docs or code. The `commit-msg` hook enforces it.
   Commit only when asked. Never force-push `main`.
4. **License hygiene.** The tree is MIT. GPL code (d2decomped, D2Vita) and DevilutionX code
   (Sustainable Use License) are **design references only**: read their docs and behaviour, never
   copy code, tables or assets out of them. Cite what you learned from in `docs/port/`.
5. **A tree that fails to link beats a binary that runs wrong** (upstream's rule, and ours). Every
   shim symbol is `real`, `stub-ok` (provably unreachable or harmless, with the reason) or
   `stub-todo`. Every stub logs its first call. No silent `return 0`.

## Scope

- **Target is LoD**, not classic. Classic-only (`-classic`-style data set, no `d2exp.mpq`) is a
  measured fallback, chosen only if the Phase 1 memory profile proves LoD can't fit, and the
  decision gets recorded in `PORTING_LOG.md` with numbers.
- **Controller support is in scope** and is first-class, not a Phase 3 nicety. See
  `docs/port/controller.md`.
- Out of scope: Battle.net, realms, online play, anti-cheat, anything multiplayer beyond a stubbed
  Winsock.

## Where code goes

| Path | What |
|-|-|
| `Redivivus/port/prelude.h` | Forced include (`-include`). Calling conventions, `__declspec`, MSVC intrinsics. Keeps `_WIN32` undefined so `d2_platform.h` takes its non-Windows path. |
| `Redivivus/port/win32/` | The fake Windows: files, heap, sync, threads, time, registry (ini-backed), windows/messages, module/version queries, PE header fakes. Grouped by area, one `.cpp` per area. |
| `Redivivus/port/backend/sdl/` | Phase 1 presentation, audio, input (i686 Linux, SDL2). |
| `Redivivus/port/backend/ps2/` | Phase 2: gsKit/GS (PSMT8 + CLUT), audsrv, padman, ps2mouse/ps2kbd, bdm/fileio. |
| `Redivivus/port/input/` | Platform-neutral input: the action layer and controller scheme. No SDL or ps2sdk types. |
| `Redivivus/port/link_data.cpp` | Portable replacement for `Redivivus/d2_link_support.s`, **generated by script** (`tools/port/gen_link_data.py`) from the `.s`, never by hand. |
| `cmake/linux-i686-sdl.cmake`, `cmake/ps2-ee.cmake` | Port toolchains. Port builds are gated by `-DREDIVIVUS_PORT=ON`; the stock mingw build must keep working unchanged. |
| `tools/port/` | Containers, smoke tests, input replay, generators. |
| `docs/port/` | Plan, controller design, `symbols.tsv` (the shim checklist). |
| `PORTING_LOG.md` | Append-only engineering log: each stub, each alignment fix, each memory measurement, each decision. Dated. |

Backends implement the interfaces in `Redivivus/port/win32/` and `Redivivus/port/input/`; game-facing
code never includes a backend header. The renderer is D2Gdi's software path (`Source/D2Gdi/Renderer/Windowed.cpp`)
presented through a fake `CreateDIBSection`/`BitBlt`/`StretchDIBits`. D2DDraw, D2Direct3D and D2Glide
are dropped from port links. Sound is a fake `IDirectSound`/`IDirectSoundBuffer` vtable under D2Sound.

## Builds

Fresh clone, once: `git config core.hooksPath tools/hooks`. Host is Apple Silicon. The Phase 1
container runs i686 under qemu (slow but correct), and the ps2dev image is native arm64.

```sh
# Phase 0: stock Windows build (must stay green; it's the reference binary)
cmake -S . -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-i686.cmake -DCMAKE_CXX_COMPILER_LAUNCHER=ccache
cmake --build build                         # -> build/d2.exe

# Phase 1: i686 Linux + SDL2, inside the container (macOS can't run 32-bit code)
tools/port/linux-i386.sh cmake -S . -B build-linux -G Ninja -DREDIVIVUS_PORT=ON \
  -DCMAKE_TOOLCHAIN_FILE=cmake/linux-i686-sdl.cmake
tools/port/linux-i386.sh cmake --build build-linux
# sanitizer config: add -DREDIVIVUS_PORT_SANITIZE=ON, build dir build-linux-asan

# Phase 2: PS2 EE, inside ps2dev/ps2dev:v2.0.0 (native arm64 image)
tools/port/ps2.sh cmake -S . -B build-ps2 -G Ninja -DREDIVIVUS_PORT=ON -DCMAKE_TOOLCHAIN_FILE=cmake/ps2-ee.cmake
tools/port/ps2.sh cmake --build build-ps2
```

Build dirs are `build*/` and are ignored. A full build is minutes: use ccache, build in the
background, and don't rebuild to check something a header read can answer. Let the linker drive the
shim: build with `-Wl,--unresolved-symbols=report-all`, diff against `docs/port/symbols.tsv`, and
keep the TSV current in the same commit as the shim change.

## Definition of done for a change

- Stock mingw build still links with no undefined symbols (`tools/check-build.sh` semantics).
- Port build for the touched phase builds; the headless smoke test passes if it exists for that phase
  (`tools/port/smoke.sh`: boot → single player → create character → Rogue Encampment → frame dump).
- Alignment-sanitizer clean on the paths you touched. Every UBSan alignment report is a future
  MIPS address-error crash: fix it, don't suppress it.
- `symbols.tsv` and `PORTING_LOG.md` updated when the change touches the shim, memory or a decision.
- No new `(verify)` claim in docs without saying how it was or will be checked.

## PS2 facts that bite

- 32 MB EE RAM is the constraint that decides everything. Measure (peak RSS, Fog pool stats in town,
  Act 5, busy fights) before optimising, and log the numbers. PCSX2's extended-RAM mode is a bring-up
  crutch, never a shipping assumption.
- No unaligned loads on MIPS. Byte buffers cast to structs (DS1, DCC, `.d2s`, packets, MPQ tables)
  crash. Fix with `memcpy`-based loads in hand-written code, or report the generator form upstream.
- EE FPU is single precision and not IEEE: no NaN/inf/denormals; `double` is software. Treat any
  NaN test, divide-by-zero or double-dependent RNG/physics as suspect.
- EE threads are priority-scheduled without time slicing: every shim wait or spin must yield.
- GS has 4 MB eDRAM; NTSC is 640×448 (scale or letterbox the 640×480 frame).

## Upstream

- `upstream` is fetch-only. Sync: `git fetch upstream && git switch -c sync/upstream-YYYYMMDD main && git merge upstream/main`,
  build, then fast-forward `main`. Merge, don't rebase, `main`: it's public.
- Fixes that belong to Redivivus (a toolchain fix, a generic Linux/SDL target, a generator bug,
  a Ghidra name/type) are written so they can go upstream: one claim, addressed by function address,
  with evidence. Follow `CONTRIBUTING.md` and `agent/skills/redivivus/SKILL.md` for which door.
  Draft upstream issues and PRs for the owner to send; never file or comment upstream yourself.
- The Ghidra databases (Windows and Mac 1.14d) are readable through the redivivus MCP plugin.
  Blizzard's Mac build is the best map of how Blizzard itself abstracted Win32; check its paired
  function before inventing a shim's semantics.

## Working style

- Plan in phases with exit criteria (`docs/port/PLAN.md`); don't start Phase N+1 work while N's exit
  criteria are open, except controller work, which develops on the Phase 1 SDL backend.
- Small, reviewable commits. Conventional prefix with scope: `port(shim): …`, `port(sdl): …`,
  `port(ps2): …`, `port(input): …`, `build: …`, `docs: …`, `tools: …`. Imperative, ≤72 chars, a body
  saying *why* when it isn't obvious.
- Measure, don't guess. When a claim can be checked against source, the Ghidra DB or a run, check it.
- When you hit something unverifiable here (real hardware, BIOS, the owner's game install), say so
  and stop rather than simulating it.
