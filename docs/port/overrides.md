# Port overrides

Generated functions a port build replaces with a hand-written definition, without
editing `Source/`. Mechanism (`cmake/port.cmake`, `HS_PORT_OVERRIDES`): after the
module's library is built, `objcopy --weaken-symbol` weakens the generated definition
in the archive, so the strong one in `Redivivus/port/overrides/` wins at link
(same-file callers too: GCC calls go through symbol relocations). A file-static
the override needs is renamed and globalized the same way.

An override is a last resort and carries its retire condition. Every one here is
also something to report upstream.

| Function | Module | Why | Retire when |
|-|-|-|-|
| `D2CMP::Pallete::PALETTE_LoadFromFile` | D2CMP | Generator **frame artefact**: the end of the path buffer is computed as `&szInlineNameBuf + 3`, which lands on `nStrEndOffset1 - 1` only with VC8's frame layout. GCC puts the scalar 0x104 bytes away, `.dat` goes astray, and entering a game halts (Fog halt line 57). | Upstream generator fix (issue to file: generator bug, function address from the Ghidra DB). |
| `D2CMP::Pallete::PALETTE_GetItemPalette` (and `PALETTE_LoadFromFile`'s target) | D2CMP | **Memory**: D2CMP and D2Win each kept a 236 KiB item palette table, filled from the same eight files into the same sets; D2CMP reads only those rows. Both now use D2Win's `gaItemPaletteTransformData`, and `--gc-sections` drops D2CMP's (`overrides/d2cmp.cpp`). Not a defect: a port policy. | Never on a 32 MB target. |
| `D2CMP::SRC::GfxHash::GFXHASH_CalcDirectionIndex` | D2CMP | **Null read**: `SPRITECACHE_LoadDCC` returns null for a sprite it can't load and its callers pass that on; this function reads through it. Entering a game does that four times (player, class 0, mode 0): PCSX2 lets it through, hardware would fault. A null entry now reads as one with the "no data" flag set, logged (`overrides/gfxhash_null.cpp`; the rest is the generated body). | Upstream report: callers of `SPRITECACHE_LoadDCC` don't check for null. |
| `D2gfx` renderer selector (references renamed, `HS_PORT_OVERRIDES`) | D2gfx | **Memory**: `D2GFX_Initialize`'s table of renderer function tables kept DirectDraw, Glide and Direct3D in the link; the references now name empty tables (`overrides/renderers_dropped.cpp`), the game only ever selects GDI, and the three renderers drop out (with the palette table, 485 KiB of program image on the EE). | A port grows a second renderer. |
| `D2CMP::SRC::LRUCache::LRUCACHE_Unlink` | D2CMP | Blizzard's null write unlinking a list's only node. Upstream fixes it at runtime by rewriting x86 `CALL rel32`s (`Redivivus/d2_patch.cpp`), which can't work on MIPS. | Upstream moves the fix to a link-level or generator-level form. |

## Wraps

Interposed rather than replaced (`HS_PORT_WRAPS`): before the module's archive is built, the
definition in one object file is renamed to `hs_orig_<symbol>`; every caller outside that object
reaches the hand-written wrapper, which calls the original.

| Function | Module | Why | Retire when |
|-|-|-|-|
| `Storm::Source::SMem::SMemCalculateAllocationLayout` (static) | Storm | **Generator defect**: emits `(n ? 7 : 0) + n` for the original `(n + 7) & ~7`, so every Storm block is 15 bytes over its request and none is 8-aligned. Reached via its section, so on MIPS its entry is patched at first `SMemAlloc` to jump to a corrected copy (`overrides/storm_align.cpp`); the static and Storm's two memory flags are globalized for it. | Upstream generator fix (issue to draft). |
| `Storm::Source::SMem::SMemAlloc` | Storm | Doesn't round request sizes, so later blocks start at odd addresses (Storm's archive records at 0x…2F3); on MIPS their 32-bit fields are unaligned loads and lookups in every archive but the first failed. The wrapper rounds every request up to 8 bytes. | Never on MIPS (it's Blizzard's allocator behaviour), unless upstream emits an aligned SMem. |
| `D2CMP::SRC::SpriteCache::GFX_InitCelDataCache` | D2CMP | **PS2 memory budget**: the game sizes the sprite cache from RAM (24-64 MB); on a target reporting 32 MB or less the wrapper caps it at 2 MB (it held 5.2 MB in town; 3 MB fitted until sound took 1.6 MB of main RAM, and 2.5 MB failed on fragmentation after minutes in a fight). Not a defect: a port policy. | Never on a 32 MB target, unless the cache moves to a budget set elsewhere. |
| `D2CMP::SRC::SpriteCache::GFX_InitLRUCache` | D2CMP | **PS2 memory budget**: the game gives the tile LRU a flat 6 MB; it grows as the player explores. On a target reporting 32 MB or less the wrapper (in `sprite_cache_cap.cpp`) caps it at 2 MB. Costs speed in busy areas (15 FPS in Harrogath's lower town). Not a defect: a port policy. | Never on a 32 MB target. |
| `Fog::Memory::Alloc`, `AllocClientMemory`, `AllocServerMemory`, `ReAllocServerMemory`, `FreeClientMemory`, `FreeServerMemory`, `FreeMemoryPool` | Fog | **PS2 memory budget**: on a target reporting 32 MB or less, requests over 256 bytes skip Fog's power-of-two pools and get their exact size from malloc, tracked per pool manager so `FreeMemoryPool` still frees them (`overrides/fog_exact_alloc.cpp`). Town peak 36.8 -> 27.5 MB. Not a defect: a port policy. | Never on a 32 MB target. |
| `Storm::Source::SFile::SFILE_SearchHashTable` (static) | Storm | **PS2 memory budget**: MPQ hash tables are mostly empty slots (d2data.mpq: 10,815 of 65,536). On MIPS its entry is patched to a search over a compacted table built at an archive's first lookup (`overrides/mpq_compact_index.cpp`); the static and `SFILE_Hash` are globalized for it. 2.5 MB freed. Not a defect: a port policy. | When the port reads its own disc archive format. |
| `Storm::Source::SMem::SMemFree`, `SMemReAlloc` (and `SMemAlloc`, through `storm_align.cpp`) | Storm | **PS2 memory budget**: Storm keeps a 64 KiB heap window per allocating source line (2.2 MB reserved for 0.3 MB used in town). On a target reporting 32 MB or less, requests below 0xfe88 bytes get their exact size from malloc behind an 8-byte header (`overrides/storm_exact_alloc.cpp`), honouring flags 8 (zero) and 0x10 (realloc in place only). Not a defect: a port policy. | Never on a 32 MB target. |
| `D2Win::Src::D2WinArchive::IMAGE_LoadDC6`, `D2Win::D2WinAnimImage` (constructor) | D2Win | **PS2 memory budget**: the class-select screen loads all seven classes' animations (12.3 MB). On a target reporting 32 MB or less, the walk and selected rows are skipped at load and loaded per class when its control leaves idle, freed when it returns (`overrides/charcreate_lazy.cpp`). Not a defect: a port policy. | Never on a 32 MB target. |
| `D2Client::UI::Draw::DRAW_UI`, `InitializeUI`, `D2Client::UI::ui::UI_LoadAllPanelAssets` (and three D2Client statics globalized: `pSpellsClassSkilltree`, `gpInvMercBodyImage`, `WaypointWayGateBackGround`) | D2Client | **PS2 memory budget**: entering a game, D2Client loads every panel's art and keeps it until the game ends (1.6 MB of closed panels in a Black Marsh fight). On a target reporting 32 MB or less the wrapper loads a panel's art when its `GFX_bShowUIFlag` is set and frees it 50 frames after it closes (and right after the game loads it, entering a game): skill tree, character panel, trade window, mercenary inventory, party screen, waypoint list, and the automap tilesets of the other acts (`overrides/panel_art_lazy.cpp`; each image is read only by its panel's draw under `DRAW_UI`). Not a defect: a port policy. | Never on a 32 MB target. |
| `D2Hell::D2FILE_AllocAndLoadD2File` | D2Hell | **Diagnostic**: the whole-file loader allocates every buffer from one line of its own; the wrapper (in `fog_exact_alloc.cpp`) moves the block to its caller's file and line in the memory report's per-owner tally and logs the first 400 loads of 32 KiB and up by name. | When the memory report no longer needs owners. |
| `D2CMP::SRC::Codec::CODEC_DecompressAllFrames` (wrap, `overrides/dcc_timing.cpp`) | D2CMP | **Speed**: times decodes and counts the files decoded (`dcc:` lines). On the PS2 it also puts decodes through a second-level cache in the IOP's spare RAM (`backend/ps2/iop/l2.c`): a hit is restored as the decoder leaves it (output block from the same pool and tag, the direction offsets in the decode state, the size); the first 64 hits are checked byte for byte against a real decode. 73% of decodes in a Black Marsh fight became 2.8 ms copies (PORTING_LOG, "a second sprite cache"). Not an upstream report: a port policy. | Never; the cache answers "no" on SDL. |
| `memset`, as called from `Source/D2CMP/SRC/Codec.cpp` (a reference, not a definition) | D2CMP | **Speed**: for each direction it decodes, `CODEC_DecompressAllFrames` clears its block table twice: pass 1 the blocks it covers, pass 2 the whole 110 KiB table, on the same bounds and iterator (4 MB of memset a frame in a busy fight). The redirect (`overrides/dcc_clear.cpp`) shrinks the whole-table clear to the size of the pass-1 clear before it. `dcc_timing.cpp` decodes the first 200 directions both ways and logs that the outputs match (200 of 200, 8% faster a decode). Not a defect in Blizzard's terms (same output), so not an upstream report. | Never; harmless if the decoder is replaced. |
| `D2Client::Sound::SoundHdr::SOUNDHDR_SetGlobal4` | D2Client | **PS2 memory budget**: the client keeps whole WAVs in main RAM under a budget of 10% of RAM above 11 MB, at least 3 MB. On a target reporting 32 MB or less the wrapper (in `sprite_cache_cap.cpp`) caps it at 448 KiB; full, the game evicts the least recently used sound or skips loading one. Its samples get a 512 KiB arena of their own (`fog_exact_alloc.cpp`), so their churn can't fragment the heap. Not a defect: a port policy. | Never on a 32 MB target. |
| `D2Client::Sound::SoundHdr::SOUNDHDR_Init` | D2Client | **PS2 memory budget**: after sounds.txt loads, every sound whose file is over 128 KiB is switched to the table's Stream column (played from the archive through Storm's streaming, a chunk at a time), with Stereo set from the file's header (`overrides/sound_stream_long.cpp`; 166 of 4,698 sounds, 1.2 s at game start). Also routes around a Blizzard bug: `SOUNDHDR_EvictLeastRecentlyUsed` computes its target unsigned, so a file bigger than the whole budget always loads. | When the bug is fixed upstream and the budget holds. |
| `D2Sound::Src::D2SoundFast::SOUND_LoadWavFile`, `SOUND_PlaySoundEffect` (and `gpWavFileCacheListHead`, `gpaSoundEffectBuffers` globalized) | D2Sound | **PS2 memory budget**: the main menu loads every class's select and deselect line at once (3.9 MB); creating a character ran out of memory. On a small-RAM target voice lines (`sfx\cursor\intro\`) load when one is played, and the others are freed once no effect buffer plays them (`overrides/sound_stream_long.cpp`; in the scripted new-character run no voice line was requested at all, so the on-demand load is unexercised). Not a defect: a port policy. | Never on a 32 MB target. |
| `Storm::Source::SFile::SFILE_HandleAsyncReadError` (static; entry patched on MIPS) and `lpCriticalSection_00779068`, globalized | Storm | **Race**: the I/O thread checks a stream read's stream, then calls this handler, which takes the stream lock and writes through the stream's buffer; `SFileDdaEnd`, on another thread, nulls that stream and frees its record under the lock. Ended in between, the handler called through null and the EE jumped to 0 (a long fight session). The entry jumps to a guard that takes the lock, returns if the stream is gone, and runs the original (through a trampoline) holding it (`overrides/storm_stream_race.cpp`). | Upstream report: a Storm race (the window is a few instructions on Windows). |
